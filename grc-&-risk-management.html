Project 3: Cyber GRC & Azure Cloud Governance Platform

A practical governance, risk and compliance case study demonstrating how ISO 27001-style principles can be applied to cloud governance, risk detection, policy enforcement and audit evidence collection in Microsoft Azure.

← Back to Projects View project evidence →

1. Overview

This project was designed to demonstrate how governance, risk and compliance principles can be applied in a practical cloud environment. Rather than focusing only on documentation, the project shows how a lightweight ISMS-style approach can be supported by technical controls in Microsoft Azure.

The solution is based on a simulated organisation, Helios Energy Analytics, and focuses on cloud governance, risk visibility, compliance monitoring and evidence collection.

2. Scope & Objectives

  • Design a practical GRC model aligned to ISO 27001 principles.
  • Apply governance controls using Azure Policy and policy initiatives.
  • Identify common cloud risks such as missing tags, public access and non-approved regions.
  • Use Azure Resource Graph to query and validate compliance findings.
  • Create an audit-ready evidence trail to support governance reporting.
  • Demonstrate how automation can support recurring compliance checks.

3. ISMS & Risk Design

I designed a lightweight ISMS-style approach focused on accountability, traceability and proportionate control selection. The aim was to link business risk, cloud assets, ownership and technical controls in a way that would be easy to understand and maintain.

  • Defined cloud resource ownership and accountability requirements.
  • Mapped key risks to practical control areas such as access, storage and network security.
  • Used tagging as a governance mechanism for ownership and auditability.
  • Created a structure for reviewing exceptions, policy violations and residual risk.

4. Governance, Policies & Procedures

Governance was treated as a core part of the solution. I created an Azure Policy initiative called Helios Governance Baseline to enforce and monitor key cloud controls at subscription level.

  • Mandatory ownership tagging to support accountability and remediation.
  • Approved region controls to support location and data residency requirements.
  • Storage security policies to reduce public exposure risk.
  • Audit and deny effects to demonstrate both monitoring and enforcement.
  • Evidence collection through screenshots, policy outputs and stored artefacts.

5. Outcomes & Lessons Learned

The project demonstrated how a governance model can be translated into practical cloud controls. It also highlighted how policy enforcement can create real operational constraints if dependencies, tagging and resource behaviour are not considered during design.

  • Improved visibility of non-compliant cloud resources.
  • Clear linkage between governance objectives and technical enforcement.
  • Better understanding of how Azure Policy supports cloud compliance.
  • Practical experience troubleshooting policy, deployment and monitoring issues.

6. Applied Case Study: Azure Cloud Governance (Helios Platform)

To complement the ISMS design, I implemented a practical Azure governance solution. The objective was to demonstrate how GRC principles can be operationalised through policy enforcement, compliance monitoring, risk detection and audit evidence.

Governance Implementation

  • Created an Azure Policy Initiative named Helios Governance Baseline.
  • Applied controls for mandatory tagging, approved regions and storage security.
  • Assigned the policy initiative at subscription level to simulate enterprise governance.
  • Used policy enforcement to detect and prevent non-compliant resource deployment.

Risk Identification

The environment was deliberately configured with realistic misconfigurations to demonstrate how cloud governance controls detect and classify risk.

  • High risk: public storage exposure.
  • High risk: unrestricted inbound network access.
  • Medium risk: resources deployed outside approved regions.
  • Medium risk: missing ownership and governance tags.

Detection & Monitoring

Azure Resource Graph was used to query the environment and validate compliance findings. This provided a repeatable way to identify missing tags, storage risks, regional violations and governance drift.

Automation

A timer-triggered Azure Function was introduced to simulate automated compliance checks. This demonstrates how governance monitoring can move from manual review into a repeatable, scheduled process.

Evidence & Audit Readiness

Compliance outputs and supporting artefacts were stored in Azure Storage to simulate an audit-ready evidence repository. This supports traceability and shows how governance findings can be retained for review.

Challenges

  • Azure Policy blocked deployments where required tags were missing.
  • Auto-created monitoring resources failed policy checks because they did not inherit the required governance tags.
  • Function App deployment was affected by regional quota limitations.
  • Some dashboard and query outputs required adjustment before producing useful results.

Resolution

  • Aligned resource configuration with policy requirements before deployment.
  • Created compliant supporting resources manually where automatic deployment was blocked.
  • Adjusted Resource Graph queries to improve accuracy and usability.
  • Used alternative regions where appropriate to overcome quota constraints.
  • Separated the written case study from the evidence pack for a cleaner portfolio presentation.

Outcome

The project demonstrates the full GRC lifecycle in practice: defining governance requirements, enforcing controls, detecting non-compliance, troubleshooting issues, and collecting evidence for audit and reporting.

The implementation aligns with ISO 27001 control themes such as access control, asset management, operational security and network security, as well as NIST CSF functions including Identify, Protect and Detect.
