SIEM Visibility & Detection Case Study

Establishing security visibility through log collection, detections and a lightweight incident response workflow — linking alerts to business risk and operational impact.

1. Overview

Project context and goals.

Lab projectSplunk

Project Overview

This project focuses on building practical SIEM experience using Splunk. The goal is to move from raw log data to meaningful alerts and investigations using a structured, risk-aware approach that mirrors how SOC and security teams operate in practice.

2. Scope & Assumptions

Environment and constraints.

Scope

Lab Environment

  • Windows host and Linux host running as lab virtual machines.
  • Focus on authentication events, system activity and core security logs.
  • Full flow objective: log → event → alert → investigation.
  • Splunk deployed as the SIEM platform for testing and configuration.

3. Log Sources & Onboarding

Which sources were selected and why.

OnboardedWindows Security

Authentication & System Logs

  • Logon success and failure events, account lockouts.
  • System logs covering key services and security-relevant activity.
OnboardedSysmon

Sysmon Telemetry

  • Process creation events with command-line arguments.
  • Network connection events for lateral movement detection.
  • Enriched endpoint visibility beyond native Windows logs.

4. Detections & Use Cases

Detection rules built and attack patterns covered.

RiskBrute force

Credential Abuse

Multiple failed logins followed by success from the same source — brute force or credential stuffing indicator.

RiskExecution

Suspicious PowerShell

PowerShell launched with encoded command arguments — common obfuscation technique used to bypass defences.

RiskPersistence

Privilege Escalation

New local account creation or addition to admin group — indicators of persistence or privilege escalation activity.

DetectionAfter-hours

Off-Hours Authentication

Authentication events outside expected working hours — potential indicator of unauthorised access or account compromise.

5. Dashboards, Triage & Investigation

Visibility tools and investigation workflow.

BuiltDashboard

Security Dashboard

  • Failed logins, account lockouts and key security events surfaced.
  • Alert views configured for rapid triage and prioritisation.
  • Single-pane visibility linking technical events to operational context.
DocumentedWorkflow

Incident Handling Workflow

  • Alert review and triage against defined severity thresholds.
  • Enrichment and context gathering to support decisions.
  • Escalation criteria and potential containment steps.
  • Documentation of findings and improvement recommendations.

6. Lessons Learned & Next Steps

What I took from the project and what comes next.

Lessons

Key Learnings

  • Noise reduction and alert tuning are critical before go-live.
  • Understanding normal behaviour is a prerequisite for defining suspicious.
  • Detection coverage should be mapped, not assumed.
Future

Planned Enhancements

  • Additional log sources: cloud platforms and SaaS applications.
  • Advanced correlation rules across multiple systems.
  • Formal playbook or SOAR-style automation workflow.
  • MITRE ATT&CK coverage mapping and gap analysis.
Outcome: A structured SIEM build demonstrating log onboarding, detection engineering, dashboards, alert configuration and automation — approached from a risk-based perspective rather than purely as a tooling exercise.
