Cyber GRC & Azure Cloud Governance Platform

A practical GRC case study applying ISO 27001-style principles through Azure Policy enforcement, risk detection, compliance monitoring and audit evidence collection.

1. Overview

Project context — Helios Energy Analytics simulated organisation.

GRCAzureISO 27001

Project Overview

This project demonstrates how governance, risk and compliance principles can be applied in a practical cloud environment. Rather than focusing solely on documentation, it shows how a lightweight ISMS-style approach can be supported by technical controls in Microsoft Azure.

The solution is based on a simulated organisation — Helios Energy Analytics — and focuses on cloud governance, risk visibility, compliance monitoring and audit evidence collection.

2. Scope & Objectives

What this project set out to demonstrate.

Scope

Objectives

  • Design a practical GRC model aligned to ISO 27001 principles.
  • Apply governance controls using Azure Policy initiatives.
  • Identify cloud risks: missing tags, public access, unapproved regions.
  • Use Azure Resource Graph to query and validate compliance findings.
  • Create an audit-ready evidence trail for governance reporting.
  • Demonstrate automation supporting recurring compliance checks.

3. ISMS & Risk Design

Lightweight information security management system design.

DesignedISMS

Risk Framework

  • Cloud resource ownership and accountability requirements defined.
  • Key risks mapped to control areas: access, storage, network security.
  • Tagging used as a governance mechanism for ownership and auditability.
  • Structure created for exceptions, policy violations and residual risk.

4. Governance Implementation

Azure Policy initiative and enforcement controls.

ImplementedAzure Policy

Helios Governance Baseline

  • Custom Azure Policy Initiative applied at subscription level.
  • Mandatory ownership tagging for accountability and remediation.
  • Approved region controls for data residency requirements.
  • Storage security policies to reduce public exposure risk.
  • Audit and deny effects for monitoring and active enforcement.
DetectedRisk identification

Risks Identified

  • High: public storage exposure.
  • High: unrestricted inbound network access.
  • Medium: resources outside approved regions.
  • Medium: missing ownership and governance tags.

5. Detection, Automation & Evidence

Resource Graph queries, Azure Functions and audit repository.

ImplementedResource Graph

Compliance Detection

Azure Resource Graph queries used to identify missing tags, storage risks, regional violations and governance drift across the subscription in a repeatable way.

ImplementedAzure Function

Automated Compliance Checks

Timer-triggered Azure Function introduced to simulate scheduled compliance monitoring — moving governance from manual review to a repeatable, automated process.

ImplementedAudit readiness

Evidence Repository

Compliance outputs and artefacts stored in Azure Storage to simulate an audit-ready evidence repository supporting traceability and governance reporting.

6. Challenges & Resolution

Real-world issues encountered and how they were resolved.

Issue

Policy Blocked Deployments

Deny policy required Owner tags and blocked auto-created monitoring resources that did not inherit governance tags.

ResolutionCreated compliant supporting resources manually and aligned all deployments with policy requirements before deploying.
Issue

Function App Deployment

Function App deployment was affected by regional quota limitations during implementation.

ResolutionUsed alternative regions where appropriate and adjusted Resource Graph queries to improve accuracy.
